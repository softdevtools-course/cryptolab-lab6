# CryptoLab · локальный прототип ЛР №6

Готовый HTML-клиент и FastAPI-сервер проводят студента через шесть технических
шагов из [спецификации курса](https://github.com/denrad/course/blob/main/02-practice/lab-06-cryptolab-spec.md):

1. Расшифрование общего примера и одноразового задания.
2. Создание двух личных пар ключей и подтверждение владения ими.
3. Получение и проверка двух X.509-сертификатов учебного CA.
4. Подпись своим и временным ключом, проверка изменённого текста.
5. Гибридный пакет AES-GCM + RSA-OAEP от студента серверу.
6. Ответный пакет сервера и расшифрование личным ключом студента.

Полностью зелёная полоса означает «Техническая часть выполнена». Кнопка
«Отправить на проверку» создаёт одну запись сдачи со статусом «Ожидает проверки»;
она не означает автоматическое принятие преподавателем.

## Запуск

Из каталога этого проекта:

```bash
python3 -m pip install -e '.[test]'
python3 -m app.ca init
python3 -m app.service init
python3 -m uvicorn app.main:app --host 127.0.0.1 --port 18766
```

Команды `app.ca init` и `app.service init` выполняются **только при первом
запуске**. Повторный вызов не перезаписывает существующие ключи. Откройте
`http://127.0.0.1:18766/`. Для проверок: `pytest -q` и `npm test` (нужен Node.js).

Приватное тестовое размещение для преподавательского просмотра доступно по
`https://lab-06.course.denrad.dev/` после входа в exe.dev. Оно использует
отдельный CA и отдельную базу; его контрольный отпечаток отличается от
локального. Устройство VM и команды диагностики описаны в
[deploy/README.md](deploy/README.md).

CA и отдельный ключ серверного участника находятся в `.local-data/ca/` и
`.local-data/service/` вне Git. Закрытые ключи создаются с правами `0600`.
Контрольный отпечаток корня получают командой `python3 -m app.ca fingerprint`
и передают студенту отдельно от страницы. Не публикуйте закрытые ключи.
Учебные файлы для первого шага и открытый сертификат CA стенда описаны в
[examples/README.md](examples/README.md). Общие учебные закрытые ключи в этой
папке опубликованы намеренно и не используются CA или серверным участником.

## Хранение и проверка

Личные закрытые ключи студента создаются как неэкспортируемые `CryptoKey` и
сохраняются в IndexedDB браузерного профиля. Сервер хранит открытые SPKI,
сертификаты, прогресс и одну запись сдачи в `.local-data/state.sqlite3` с WAL.
Прогресс и учебная запись сохраняются после перезапуска сервера, пока браузер
сохраняет cookie и IndexedDB. Очистка данных сайта или смена профиля лишит
студента доступа к закрытым ключам; восстановление доступа пока не реализовано.
Незавершённые одноразовые задания после перезапуска сервера нужно получить заново.

В пакете открыты маршрутные поля и шифротекст. AES-GCM аутентифицирует критические
поля через AAD, а сервер проверяет адресата и серийный номер сертификата. Для
исходящего пакета сервер хранит SHA-256 канонического JSON, но не хранит его JSON
или открытый текст. Входящий пакет содержит одноразовый секрет; сервер хранит
только его SHA-256 до проверки. Формат версии 1 ограничивает поля ASCII и
фиксирует порядок AAD; это проверяется тестами Python и Node.js.

Преподаватель может выгрузить локальный журнал и сдачи в CSV:

```bash
python3 -m app.export --output-dir .local-data/export
```

Эта команда работает локально с файлом БД; CSV содержит случайные учебные
`actor_id`, а не ФИО. Связь с реальным студентом ещё нужно определить.

Для повторяемого полного прохода через реальный локальный HTTP-сервер можно
запустить `node scripts/live_student_walkthrough.mjs <контрольный-отпечаток-CA>`.
Скрипт создаёт новую демозапись, использует те же Web Crypto-модули, что и
страница, проходит все шесть шагов и создаёт одну тестовую сдачу. Он проверяет
протокол и сервер, но не клики, вёрстку и IndexedDB в браузере.

## Границы прототипа

- Общие `examples/training-key.pem` и `examples/wrong-key.pem` опубликованы
  намеренно и не являются личными ключами студента или CA.
- Локальный режим работает на `127.0.0.1` по HTTP. Приватное превью на exe.dev
  использует HTTPS и доступ только для владельца VM. Перед студенческим пилотом нужны
  идентификация студентов, CSRF-защита, ограничения частоты/размера,
  резервное копирование CA и БД, политика отзыва и сброса доступа.
- Cookie локальной демозаписи действует 30 дней. Истёкшие задания в этом
  прототипе очищаются при перезапуске; автоматическая очистка ещё не добавлена.
- Сертификаты студента действуют семь дней. После истечения их можно выпустить
  повторно и сверить отпечаток; уже пройденные технические шаги сохраняются.
- Прототип не доказывает личность студента и не выполняет преподавательскую
  проверку объяснений. Не вводите реальные секреты.
